01 The question underneath the headlines

“An AI solved it.” How would you know?

The same year produced a second, quieter story: the people whose job is to check these results saying, in public, that checking them is getting hard.

Every one of these stories is the same story. A system produced an answer, and the interesting difficulty was not producing it — it was establishing what had actually happened.

That is a measurement problem, and measurement problems have known solutions. This workshop builds one, from nothing, in front of you. By the end you will have an apparatus that can say what an agent did, how reliably it does it, what it cost, and — the hard part — whether its reasoning actually supported its answer.

02 The motivation

You cannot check what you did not record.

Scoring the answer works for a model that emits one string. The moment there are tool calls and multiple turns, the thing you are evaluating is not a string — it is a trajectory, and almost all of it is invisible if you only keep the last box.

What you scoreone string problem→ model→ answer one comparison grades this completely
What happeneda trajectory problem→ model→ tool_call→ tool_result→ model→ tool_call→ tool_result→ model→ submit

Was the answer computed, or asserted? Did the tool agree with the narration? How many attempts did it take? What did it cost? None of this survives a boolean.

One reported number, four separate questions

Axis 01

Outcome

Did it reach the right answer? The only axis most reports answer.

Axis 02

Process

Does the reasoning support the conclusion? No answer key exists for this.

Axis 03

Cost

What did it spend? Per successful solve, not per run.

Axis 04

Reliability

Would it do it again? One run is not a measurement.

The headlines in part 00 report axis 1. The disquiet in part 01 is about axis 2. The next twelve parts build the apparatus that can answer all four — and it turns out you have to build them in that order, because axis 2 depends on having recorded enough to ask.

03 Session 1 begins · harness engineering

A harness is a measurement apparatus.

It is everything that is not the model: task loading, the agent interface, the tool registry, sandboxed execution, the turn loop and its stop conditions, trace recording, config pinning, fault handling, rollout orchestration, verification, aggregation, reporting.

A harness is a measurement apparatus. A judge is one instrument inside it. Harness engineering is what makes the measurement reproducible; judge hygiene is what makes that instrument trustworthy. Neither produces a meaningful number alone.

The one commitment everything else follows from

Everything downstream of execution is a pure function of an append-only event log. Execution and grading are separated by the trace — and that single seam is what makes new verifiers applicable to old runs at no cost, makes the demo network-independent, and turns reproducibility from a claim into something you can do.

The diagonal is the design: no model ever judges itself, so self-preference is eliminated by construction. Stated openly on stage: because nothing judges itself, self-preference is therefore excluded from this design rather than measured by it.

Reasoning models, and what “effort” changes

All three solvers are reasoning models: before answering, they produce an internal chain of thought whose length is controlled by an effort setting. More effort means more tokens spent thinking, more latency, and a larger bill. It does not reliably mean a better answer — Kapoor et al. (2025) found higher effort reduced accuracy in most of their runs. That is exactly the kind of fact that is invisible unless effort is pinned and recorded with every trace.

07 Build step 2 · the trace store

Build the log before you build the agent.

This will feel premature and it is not. The store is the seam the whole architecture rests on: one append-only file per (config, task), a pinned header written once on creation, and every rollout appended and flushed to disk. Nothing is ever rewritten in place, because a corpus you can rewrite is one you eventually will.

def append_rollout(rollout: Rollout, header: dict, root: Path | None = None) -> Path:
    """Append one rollout. Writes the pinned header once, on file creation."""
    p = trace_path(rollout.solver_config, rollout.task_id, root)
    p.parent.mkdir(parents=True, exist_ok=True)
    new = not p.exists()
    with open(p, "a", encoding="utf-8") as fh:
        if new:
            fh.write(json.dumps({"_header": header}, sort_keys=True) + "\n")
        fh.write(json.dumps(rollout.to_dict()) + "\n")
        fh.flush()
        os.fsync(fh.fileno())
    return p

Writes one finished rollout to disk. Append-only — nothing is ever rewritten in place.

  • open(p, "a")Append mode, always. A corpus you can rewrite is a corpus you will eventually rewrite, usually at 2am before a talk.
  • if new:The pinned config header is written exactly once, when the file is created. Every rollout in the file was produced under it.
  • os.fsyncForces the write to the physical disk. A run killed mid-batch loses nothing it had already reported, which is what makes resumption trustworthy.

08 Build step 3 · pinning the apparatus

A number without a pinned apparatus is not a measurement.

Five things decide what a run means: the model string, the temperature, the reasoning effort, the prompt, and the tool set. Change any one and every downstream figure describes a different experiment — so it had better be a different hash. The hash is printed at the top of every run, so the room sees the apparatus was pinned rather than being told it was.

core/config.pysensitive to all five
@property
def config_hash(self) -> str:
    """Sensitive to model string, prompt, temperature, reasoning effort
    and tool set.

    Change any one of the four and every downstream number is a different
    measurement, so it must be a different hash.
    """
    material = json.dumps(
        {
            "model": self.model.model,
            "temperature": self.model.temperature,
            "prompt_sha": prompt_hash(self.prompt),
            "reasoning_effort": self.model.reasoning_effort,
            "tools": sorted(self.tools),
        },
        sort_keys=True,
    )
    return hashlib.sha256(material.encode("utf-8")).hexdigest()[:12]

Turns the four things that decide what a run means into one short, comparable fingerprint.

  • model / temperatureThe obvious two. Change either and you are measuring a different system.
  • prompt_shaThe prompt is hashed rather than embedded, so the fingerprint stays short but still moves if a single character of the prompt changes.
  • sorted(self.tools)Sorted, so the same tool set always hashes the same way regardless of declaration order. Unsorted here would produce spurious hash changes and destroy comparability.
  • sort_keys=TrueSame reason, one level up: the JSON serialisation must be canonical or the hash is not a function of the config.

09 Build step 4 · the turn loop

Write the loop by hand, once.

A message list, a dict of Python functions, schemas generated from their signatures, and a while loop that calls the model, runs whatever it asked for, appends the results, and repeats until something stops it. Writing it is what makes it possible to say what a framework would have bought — retries, schema plumbing, a history abstraction — and why none of it was needed here.

Note what the loop cannot do: decide whether the answer was right. It has no key and no way to get one. That is not an oversight — it is the isolation that makes the grade a separate, later, cheaper step.

agent/loop.pythe whole loop, and it never grades
def run_rollout(task: Task, cfg: RunConfig, provider, run_idx: int,
                seed: int | None = None) -> Rollout:
    rec = TraceRecorder(task.task_id, run_idx, cfg.solver_config, cfg.config_hash, seed)
    budget = Budget(usd_cap=cfg.usd_budget, turn_cap=cfg.max_turns)
    schemas = toolmod.schemas(cfg.tools)

    messages = [
        {"role": "system", "content": cfg.prompt},
        {"role": "user", "content": task.problem},
    ]
    rec.emit("run_start", task_id=task.task_id, run_idx=run_idx, config=cfg.header())

    while True:
        try:
            budget.check("turn")
        except BudgetExceeded as e:
            rec.emit("error", fault=e.kind, message=str(e))
            return _stop(rec, "max_turns" if e.kind == "turn" else "budget_exceeded", budget)

        rec.emit("model_call", n_messages=len(messages), model=cfg.model.model)
        try:
            comp: Completion = provider.complete(messages, schemas)
        except ProviderTimeout as e:
            # A harness failure. Not a wrong answer.
            rec.emit("error", fault="timeout", message=str(e))
            return _stop(rec, "timeout", budget)
        except ProviderError as e:
            rec.emit("error", fault="provider", message=str(e))
            return _stop(rec, "error", budget)

        budget.turns_used += 1
        from agent.providers import usd as _usd
        budget.charge(comp.tokens_in, comp.tokens_out,
                      _usd(cfg.model, comp.tokens_in, comp.tokens_out))
        rec.emit("model_response", text=comp.text,
                 tool_calls=[c["name"] for c in comp.tool_calls],
                 tokens_in=comp.tokens_in, tokens_out=comp.tokens_out)

        if not comp.tool_calls:
            low = (comp.text or "").lower()
            if any(m in low for m in REFUSAL_MARKERS):
                return _stop(rec, "refused", budget, final=None)
            # No tool call and no refusal: nudge once, then let the turn cap bite.
            messages.append({"role": "assistant", "content": comp.text})
            messages.append({"role": "user",
                             "content": "Call a tool, or submit_answer if you are done."})
            continue

        messages.append({"role": "assistant", "content": comp.text or None,
                         "tool_calls": comp.tool_calls})

        for tc in comp.tool_calls:
            rec.emit("tool_call", tool=tc["name"], args=tc["args"])
            try:
                result = toolmod.call(tc["name"], tc["args"], budget)
            except toolmod.SubmitAnswer as s:
                rec.emit("final", value=s.value, reasoning=s.reasoning)
                return _stop(rec, "submitted", budget, final=s.value)
            except BudgetExceeded as e:
                # The trip kind matters: hitting the turn cap is `max_turns`,
                # hitting the spend cap is `budget_exceeded`. Flattening the two
                # would lose the distinction the taxonomy exists to make.
                rec.emit("error", fault=e.kind, message=str(e))
                return _stop(rec, "max_turns" if e.kind == "turn" else "budget_exceeded",
                             budget)
            except Exception as e:  # noqa: BLE001
                result = {"error": f"{type(e).__name__}: {e}"}
            rec.emit("tool_result", tool=tc["name"], result=result)
            messages.append({"role": "tool", "name": tc["name"],
                             "content": json.dumps(result)})

The whole tool-calling loop. Roughly fifty lines, no framework — and it never decides whether the answer was right.

  • budget.checkFirst thing each turn. The stop condition is checked before spending, not after.
  • except ProviderTimeoutCaught separately from other provider errors, so a timeout becomes the outcome timeout and not a generic failure. Distinct causes get distinct names.
  • if not comp.tool_callsA reply with no tool call is not automatically a refusal. The loop nudges once, then lets the turn cap decide — a crude stop condition, deliberately visible as such.
  • except SubmitAnswerSubmission arrives as an exception because it is control flow, not an error: it is the one tool call that ends the loop.
  • return _stop(...)Every exit path returns a recorded rollout. There is no path where something happens and no trace is written.

def schema(self) -> dict:
    """Generated from the signature, so the schema cannot drift from the code."""
    sig = inspect.signature(self.fn)
    props, required = {}, []
    for pname, p in sig.parameters.items():
        if pname in ("budget", "_ctx"):
            continue
        props[pname] = {"type": _JSON_TYPES.get(p.annotation, "string")}
        if p.default is inspect.Parameter.empty:
            required.append(pname)
    return {
        "type": "function",
        "function": {
            "name": self.name,
            "description": self.description,
            "parameters": {"type": "object", "properties": props, "required": required},
        },
    }

Generates the JSON schema the model sees from the Python signature, so the two cannot drift apart.

  • inspect.signatureThe single source of truth is the function itself. Rename a parameter and the schema follows; hand-written schemas silently describe last month's function.
  • pname in ("budget",)Harness-injected parameters are filtered out. The model is offered code; the budget is supplied by us and is none of the model's business.
  • required.appendA parameter with no default is required. The rule is read off the code rather than restated in prose that can go stale.
agent/sandbox.pyisolated, capped, and it never raises on user error
def run_python(code: str, timeout_s: int = DEFAULT_TIMEOUT_S) -> ExecResult:
    """Execute `code` in a fresh isolated interpreter. Never raises on user error."""
    try:
        proc = subprocess.run(
            [sys.executable, "-I", "-S", "-c", PREAMBLE + code],
            capture_output=True,
            text=True,
            timeout=timeout_s,
            preexec_fn=_limits,
            env={"PATH": "/usr/bin:/bin", "HOME": "/tmp"},
        )
        return ExecResult(
            stdout=proc.stdout[-4000:],
            stderr=proc.stderr[-2000:],
            returncode=proc.returncode,
            timed_out=False,
        )
    except subprocess.TimeoutExpired:
        return ExecResult("", f"timeout after {timeout_s}s", -1, True)

Executes submitted code in a fresh, isolated interpreter, and never raises on the code's own errors.

  • "-I", "-S"Isolated mode with no site packages, so the environment the model gets is the same on every machine.
  • PREAMBLE + codeSockets and the network-reaching imports are disabled before a single line of submitted code runs. A subprocess that never had the capability is easier to reason about than one that gave it up.
  • preexec_fn=_limitsCPU and file-size caps in the child. Best effort — a limit the platform refuses is skipped, and the wall-clock timeout is the backstop that always holds.
  • TimeoutExpiredA timeout returns a result with timed_out=True, not an exception. It is something that happened and must be recorded, not an error to propagate.

11 Build step 6 · the budget

Instructions do not constrain spend. Boundaries do.

The first cap in this build was written into the system prompt, and it was exceeded. That is not a surprising failure — a sentence in a prompt is a request. Refusing the next tool call is a limit. The check moved one layer down, to the tool boundary, and has held since.

core/budget.pytwo caps, and the trip kind matters
def check(self, kind: str = "usd") -> None:
    """Called immediately before a tool executes and before each turn."""
    if self.usd_spent >= self.usd_cap:
        self.trips.append("usd")
        raise BudgetExceeded(self.usd_spent, self.usd_cap, "usd")
    if self.turns_used >= self.turn_cap:
        self.trips.append("turns")
        raise BudgetExceeded(self.turns_used, self.turn_cap, "turn")

Resumption, and the retry you must not write.

A batch killed half way through and restarted must not duplicate work and must not lose it. Because the store is append-only and keyed, resumption is a read — no bookkeeping table that can drift out of step with the data. And the tempting bug: retrying a rollout that errored until it succeeds. Do that and the error rate is zero, accuracy is up, and both numbers are fiction.

def _with_backoff(fn, attempts: int = MAX_ATTEMPTS):
    """Backoff for faults that escape the loop entirely — i.e. we failed to
    obtain a trace at all.

    Note what is deliberately NOT retried here: a provider error or timeout
    that the loop caught. Those are recorded as the outcomes `error` and
    `timeout` and left in the corpus, because silently re-rolling them until
    one succeeds is precisely how a reported accuracy gets inflated. The error
    rate is a result, not a nuisance to be retried away.
    """
    last = None
    for i in range(attempts):
        try:
            return fn()
        except ProviderError as e:
            last = e
            if i == attempts - 1:
                raise
            time.sleep(BASE_BACKOFF_S * (2 ** i) * (1 + random.random() * 0.3))
    raise last  # pragma: no cover

Retries only the case where no trace was obtained at all. Read the docstring — what it refuses to retry is the point.

  • 2 ** iExponential backoff with jitter, so a batch of concurrent workers does not synchronise and hammer a recovering endpoint.
  • NOT retriedA provider error the loop caught is recorded as error or timeout and left in the corpus. Re-rolling it until it succeeds is exactly how a reported accuracy gets inflated.
  • the error rate is a resultIt describes how reliable the apparatus was that afternoon. That is information, not noise to be cleaned up.

14 Build step 9 · the metrics

One run tells you what an agent can do. Ten tell you what it will do.

pass@k is the probability that at least one of k attempts succeeds — it rises with k and flatters everything. pass^k is the probability that all k succeed. The gap between the two curves is the whole reliability story, and reporting the first without the second is the most common way an agent evaluation overstates what it measured.

pass@k  ·  at least one of k succeeds pass^k  ·  all k succeed

Schematic — exact algebra for a single task at p = 0.70, so shape rather than result. τ-bench put published pass^8 below 25% in retail for the best agent of 2024.

def pass_at_k(n: int, c: int, k: int) -> float:
    """P(at least one of k succeeds). Unbiased from n trials, c successes."""
    if k > n:
        raise ValueError(f"k={k} exceeds n={n}")
    if n - c < k:
        return 1.0
    return 1.0 - comb(n - c, k) / comb(n, k)

The probability that at least one of k attempts succeeds — estimated from n trials and c successes, without re-running anything.

  • comb(n - c, k)Counts the ways to draw k attempts that are all failures. One minus that share is the chance of at least one success.
  • if n - c < kIf there are fewer failures than k, every possible draw contains a success, so the answer is exactly 1.
  • what it hidesThis number rises toward 1 as k grows for almost any agent. On its own it flatters everything, which is why it never appears without the next function beside it.

def pass_hat_k(n: int, c: int, k: int) -> float:
    """P(all k succeed). The reliability number."""
    if k > n:

    if c < k:
        return 0.0

The probability that all k attempts succeed. This is the reliability number.

  • comb(c, k) / comb(n, k)The share of all k-subsets that consist entirely of successes. Unbiased from the trials you already have.
  • if c < kFewer than k successes means no such subset exists, so the value is 0 — not a small number, exactly zero.
  • why it matterspass@k answers 'can it'. pass^k answers 'will it'. The gap between the two curves is the whole compounding-reliability story.

def bootstrap_ci(values: list[float], stat=None, n_boot: int = 2000, alpha: float = 0.05,
                 rng: random.Random | None = None) -> tuple[float, float]:
    """Percentile interval. Resample the CLUSTER (a task), not the rollout —
    rollouts within a task are correlated, and ignoring that understates the
    interval (Miller, 2024)."""
    if not values:
        return (float("nan"), float("nan"))
    stat = stat or (lambda xs: sum(xs) / len(xs))
    rng = rng or random.Random(20260907)
    m = len(values)
    draws = sorted(stat([values[rng.randrange(m)] for _ in range(m)]) for _ in range(n_boot))
    lo = draws[int((alpha / 2) * n_boot)]
    hi = draws[min(n_boot - 1, int((1 - alpha / 2) * n_boot))]
    return (lo, hi)

A percentile confidence interval — and the choice of what to resample is the entire methodological point.

  • values[rng.randrange(m)]Resamples with replacement to build the sampling distribution of the statistic.
  • resample the CLUSTERThe values passed in are per-task rates, not per-rollout outcomes. Ten rollouts of the same problem are correlated; treating them as ten independent samples produces an interval that is far too narrow.
  • 8 problemsWith a task set this small, an interval is not optional decoration. It is the difference between an honest report and an overclaim.

def normalise(raw) -> int | None:
    """Return an integer, or None if this value needs an escape."""
    if raw is None:
        return None
    if isinstance(raw, bool):
        return None
    if isinstance(raw, int):
        return raw
    s = str(raw).strip()
    m = _BOXED.search(s)
    if m:
        s = m.group(1)
    s = s.replace("$", "").replace(",", "").replace("\\!", "").replace("\\,", "")
    s = s.replace(" ", "").strip()
    s = re.sub(r"^\+", "", s)
    if _INT.match(s):
        return int(s)
    if re.match(r"^-?\d+\.0*$", s):
        return int(float(s))
    return None

Turns whatever the model submitted into an integer, or admits it cannot. Exact, free, reproducible — and the reason a judge here would be the wrong tool.

  • _BOXED.searchPulls the value out of \boxed{...}, the single most common way a maths answer arrives wrapped.
  • replace / re.subStrips currency marks, thousands separators, LaTeX spacing and leading plus signs. Each of these is a real submission format, not a hypothetical one.
  • ^-?\d+\.0*$Accepts 608.0 as 608. Rejecting an integer for being spelled as a float would mark a right answer wrong.
  • return NoneThe honest failure. It does not guess — it hands the decision to the escape path, where it will be counted.

                continue
            parts.append(f"NARRATION:\n{text}\n")
        elif ev.kind == "tool_call" and ev.payload.get("tool") == "python_exec":
            parts.append(f"TOOL CODE:\n{ev.payload['args'].get('code','')}\n")
        elif ev.kind == "tool_result":
            res = ev.payload.get("result", {})
            parts.append(f"TOOL STDOUT:\n{str(res.get('stdout','')).strip()}\n")
        # `final`, `run_start`, `model_call` and `error` events are never rendered:
        # they carry the submission, the pinned config and provider error strings.

    if not blinded:
        parts.append(f"FINAL ANSWER: {submitted}")
        parts.append(f"OUTCOME: {graded_outcome or rollout.outcome}")

    parts.append(TASK_BLOCK)
    prompt = "\n".join(parts)

    audit = _audit(prompt, rollout, submitted, ids, blinded)
    if blinded and audit["hard_leaks"]:
        raise BlindingLeak(
            "blinding failed; these must never reach a blinded judge: "
            + ", ".join(audit["hard_leaks"])
        )
    return prompt, audit

The blinding function. It builds the judge prompt from the trace and decides what the judge is not allowed to know.

  • for ev in rollout.eventsThe prompt is assembled from the event log, not from a summary. What the judge reads is what actually happened.
  • elif tool_resultNarration, tool code and tool output are interleaved in the order they occurred, so the reasoning can be followed step by step.
  • never renderedfinal, run_start, model_call and error events are skipped — they carry the submission, the pinned config, and provider error strings that would identify the model.
  • if not blindedThe unblinded arm is the same function with a flag, adding two lines. Those two lines are the entire experiment in beat 6.
  • graded_outcomeThe unblinded arm is told the grade, not the raw execution state. Passing 'submitted' would leak nothing and the ablation would silently measure noise.

20 Blinding

Blind the judge to the outcome.

A process judge that can see the answer was correct will rationalise flawed reasoning as sound. This is the largest and least-known failure in the setup, and it is demonstrated on the same traces rather than asserted.

Goes into the prompt

  • problem statement
  • the reasoning
  • tool code
  • tool output

Stripped, and asserted absent

  • the submitted value
  • the answer key
  • the outcome
  • model identifiers
  • config, seeds, timestamps
  • usage and error strings
A bug we found in our own blinding

The first version replaced the submitted value in the narration with [REDACTED]. But that only fires when the narrated value matches the submission — which is exactly when the narration is faithful. The marker appeared on sound traces and never on flawed ones: a judge could read the verdict off a placeholder. Blinding that introduces a tell is worse than none, because it looks careful.

def _audit(prompt: str, rollout: Rollout, submitted: str, ids, blinded: bool) -> dict:
    hard = []
    for ident in ids:
        if re.search(rf"(?<![\w-]){re.escape(str(ident))}(?![\w-])", prompt):
            hard.append(f"identifier:{ident}")
    if blinded:
        for token in ("OUTCOME:", "FINAL ANSWER:", "ANSWER KEY", "config_hash", "usd"):
            if token in prompt:
                hard.append(f"metadata:{token}")
        if REDACTED in prompt:
            # Guards against reintroducing the tell described in the docstring.
            hard.append("redaction_marker_present")

    body = "\n".join(_blocks(prompt, "TOOL STDOUT") + _blocks(prompt, "NARRATION"))
    residual = bool(submitted and re.search(rf"\b{re.escape(submitted)}\b", body))
    return {
        "hard_leaks": hard,
        # NOT a leak of the outcome: the judge can see WHAT was answered, never
        # whether it was right. Reported as a corpus property, not a failure.
        "answer_recoverable_from_tool_output": residual,
        "blinded": blinded,
        "chars": len(prompt),
    }

The assertion. It fails loudly on anything the harness controls, and reports honestly on the one thing it does not.

  • (?<![\w-])...(?![\w-])Word-boundary matching for identifiers, so 'S1' inside a longer token is not a false positive while a real model name is always caught.
  • for token in (...)Outcome, answer key, config hash and usage are all banned strings in a blinded prompt. Any of them appearing raises rather than warns.
  • REDACTED in promptGuards against reintroducing the tell we removed: a placeholder that only appears on faithful narrations tells the judge the answer without it reading anything.
  • residualThe soft flag. It reports that the judge could reconstruct what was answered from tool output — true of 100% of our traces. It is not outcome leakage, because the key never enters this module, and it is why the ablation is the real measurement.
Outcome leakage

Removed by stripping the answer and the verdict. Measured by the ablation, not assumed away by the redaction.

Provenance leakage

Model names and system identifiers removed. Judges favour text that looks like their own, and preference leakage inflates verdicts across a whole family.

Position bias

In any pairwise comparison, randomise position and average over both orderings. Systematic, varies by judge — large, and free to remove.

21 The rubric

Discrete anchors. A mandatory span. Rejected at parse time.

Done wrong

“Rate the reasoning from 1 to 10.” Models do not use the middle of numeric scales consistently, so a 7 from one judge is not a 7 from another and scores stop being comparable across items.

ESTABLISHESThe reasoning is sufficient to determine the conclusion.
INCOMPLETENo error, but gaps remain before a conclusion follows.
ERRORA specific, locatable mistake.
INDETERMINATESupports no determinate conclusion at all.

And a quoted span, always. It is the cure for hallucinated criticism: a judge that cannot point at the step it objects to has not found one. “No verdict” has to mean rejected, not quietly coerced into a default — a rejected verdict is visible in the counts, a defaulted one becomes data.

def parse_verdict(raw: str | dict) -> dict:
    """Reject at parse time, not later. No quoted span, no verdict."""
    if isinstance(raw, str):
        m = re.search(r"\{.*\}", raw, re.S)
        if not m:
            raise VerdictRejected("no JSON object in judge response")
        raw = json.loads(m.group(0))
    verdict = str(raw.get("verdict", "")).strip().upper()
    span = str(raw.get("span", "") or "").strip()
    if verdict not in ANCHORS:
        raise VerdictRejected(f"verdict {verdict!r} is not one of {ANCHORS}")
    if not span:
        raise VerdictRejected("verdict arrived without a non-empty evidence span")
    return {"verdict": verdict, "span": span,
            "justification": str(raw.get("justification", "")).strip()}

Rejects a malformed verdict at parse time, rather than coercing it into something usable.

  • verdict not in ANCHORSOnly the four named anchors are accepted. A judge that invents a fifth category has not followed the rubric, and its answer is not comparable to the others.
  • if not spanNo quoted evidence, no verdict. This is the rule that removes hallucinated criticism — a judge that cannot point at the step it objects to has not found one.
  • raise VerdictRejectedRaising rather than returning a default. A rejected verdict is visible in the counts; a silently defaulted one becomes data.

22 The rotation

Two judges, from different families, never itself.

No self-judging

Self-preference is eliminated by construction rather than corrected afterwards. Judges favour text that looks like their own, and rubric anchors do not fix that.

Severity is comparable

Each model judges in exactly two roles, over two independent solver populations, so a consistently harsh model shows up in both.

The limitation, said first

Because nothing judges itself, self-preference cannot be measured here. It is excluded, not quantified. Say it on stage rather than let it be raised in Q&A.

23 Judging the judges

An unvalidated instrument is not a measurement.

Inter-judge agreement — as a headline

Raw agreement and Cohen's kappa, because raw agreement on a skewed label distribution flatters every judge. Presenting a process score while the instrument disagrees with itself is the failure this prevents.

Judge severity

Each model's rate of not saying ESTABLISHES, across both of its judging roles.

Blinding effect

The same traces judged both ways. Showing the judge that the answer was right made it measurably more forgiving of the reasoning.

Judge–human agreement

Forty traces, sampled stratified across the three solver configurations and across correct and incorrect outcomes, labelled by hand on the same rubric with the same span requirement. Reported per judge, never averaged, with n attached.

Declared on stage

Forty traces labelled by one person is single-annotator calibration, not an annotation study. Until the labels exist, report.py prints that every process figure above it is an assertion rather than a result.

def inter_judge_agreement(verdicts) -> dict:
    paired = pair_up(verdicts)
    a, b, per_cfg = [], [], defaultdict(lambda: [0, 0])
    for (cfg, _, _), byjudge in paired.items():
        if len(byjudge) != 2:
            continue
        (_, va), (_, vb) = sorted(byjudge.items())
        a.append(va)
        b.append(vb)
        per_cfg[cfg][1] += 1
        per_cfg[cfg][0] += int(va == vb)
    return {
        "n_pairs": len(a),
        "raw_agreement": (sum(x == y for x, y in zip(a, b)) / len(a)) if a else float("nan"),
        "cohens_kappa": cohens_kappa(a, b),
        "per_config": {c: (hit / tot if tot else float("nan")) for c, (hit, tot) in per_cfg.items()},
        "confusion": Counter((x, y) for x, y in zip(a, b) if x != y).most_common(5),
    }

How often the two judges agree — reported as a headline number, never a footnote.

  • len(byjudge) != 2Only traces carrying both verdicts are counted. A trace one judge rejected at parse time is excluded rather than silently treated as agreement.
  • raw_agreementThe share of items where the two labels match. Easy to read and easy to over-trust.
  • cohens_kappaAgreement above chance. On a skewed label distribution — where both judges say ESTABLISHES most of the time — raw agreement is high while the judges share almost no information. Kappa is what survives that.
  • confusionWhich pairs of labels they disagree on. Mostly ESTABLISHES against INCOMPLETE is a threshold disagreement; ESTABLISHES against ERROR is a factual one, and far more serious.

def blinding_effect(verdicts) -> dict:
    """The direct measurement of outcome leakage: on the SAME traces, how often
    does the verdict change when the judge is allowed to see the answer?"""
    blinded, unblinded = {}, {}
    for v in verdicts:
        slot = blinded if v.blinded else unblinded
        slot[(_key(v), v.judge_model)] = v.label
    common = set(blinded) & set(unblinded)
    if not common:
        return {"n": 0}
    changed = [(blinded[k], unblinded[k]) for k in common if blinded[k] != unblinded[k]]
    to_establishes = sum(1 for b, u in changed if u == "ESTABLISHES" and b != "ESTABLISHES")
    from_establishes = sum(1 for b, u in changed if b == "ESTABLISHES" and u != "ESTABLISHES")
    return {
        "n": len(common),
        "change_rate": len(changed) / len(common),
        "flipped_to_establishes": to_establishes,
        "flipped_from_establishes": from_establishes,
        "net_leniency": (to_establishes - from_establishes) / len(common),
        "blinded_unsound_rate": sum(1 for k in common if blinded[k] != "ESTABLISHES") / len(common),
        "unblinded_unsound_rate": sum(1 for k in common if unblinded[k] != "ESTABLISHES") / len(common),
    }

The direct measurement of outcome leakage: the same traces, judged both ways, differing in one flag.

  • set(blinded) & set(unblinded)Only traces judged in both conditions are compared, keyed by trace and judge. It is a paired comparison, not two independent samples.
  • flipped_to_establishesCounts verdicts that became more forgiving once the judge could see the answer was right. Direction matters — noise flips both ways, leakage flips one.
  • net_leniencyThe asymmetry. In our corpus, unsound verdicts fell from 23% to 13% when the outcome was visible: seeing the right answer made the judge ten points more forgiving of the reasoning.

def stratified(rollouts, outcomes, n: int, seed: int = 20260907):
    """Stratified across the three solver configs AND across correct/incorrect,
    so the calibration set cannot be accidentally all-easy."""
    strata = defaultdict(list)
    for r in rollouts:
        o = outcomes.get((r.solver_config, r.task_id, r.run_idx))
        if o in ("correct", "incorrect"):
            strata[(r.solver_config, o)].append(r)
    rng = random.Random(seed)
    for v in strata.values():
        rng.shuffle(v)
    picked, i = [], 0
    keys = sorted(strata)
    while len(picked) < n and any(strata[k] for k in keys):
        k = keys[i % len(keys)]
        if strata[k]:
            picked.append(strata[k].pop())
        i += 1
    return picked

Chooses which forty traces get hand-labelled. Sampling badly here quietly invalidates every judge number downstream.

  • strata[(config, outcome)]Six buckets: three solver configurations × correct/incorrect. The calibration set cannot come out all-easy or all from the strongest model.
  • keys[i % len(keys)]Round-robins across the buckets, so the set stays balanced even when one bucket runs out.
  • seed=20260907Fixed seed. Which forty traces were labelled is part of the apparatus and has to be reproducible like everything else.

def loads(text: str):
    lines = []
    for raw in text.splitlines():
        body = _strip_comment(raw)
        if body.strip():
            lines.append((len(body) - len(body.lstrip()), body.strip()))

    def parse(i: int, indent: int):
        if i < len(lines) and lines[i][1].startswith("- "):
            items = []
            while i < len(lines) and lines[i][0] == indent and lines[i][1].startswith("- "):
                rest = lines[i][1][2:].strip()
                if ":" in rest and not rest.startswith(("[", '"', "'")):
                    sub, i = parse_map_from_inline(rest, i, indent)
                    items.append(sub)
                else:
                    items.append(_inline(rest))
                    i += 1
            return items, i
        out = {}
        while i < len(lines) and lines[i][0] >= indent:
            if lines[i][0] > indent:
                raise ValueError(f"bad indent at {lines[i][1]!r}")
            key, _, rest = lines[i][1].partition(":")
            key, rest = key.strip(), rest.strip()
            if rest:
                out[key] = _inline(rest)
                i += 1
            else:
                i += 1
                if i < len(lines) and lines[i][0] > indent:
                    out[key], i = parse(i, lines[i][0])
                else:
                    out[key] = None
        return out, i

    def parse_map_from_inline(rest: str, i: int, indent: int):
        # "- key: value" opens a mapping whose siblings are indented under it
        sub = {}
        key, _, val = rest.partition(":")
        sub[key.strip()] = _inline(val.strip())
        i += 1
        child = indent + 2
        while i < len(lines) and lines[i][0] >= child and not lines[i][1].startswith("- "):
            k, _, v = lines[i][1].partition(":")
            sub[k.strip()] = _inline(v.strip())
            i += 1
        return sub, i

    data, _ = parse(0, lines[0][0] if lines else 0)
    return data

        ev = Event(t=time.time() - self._t0, kind=kind, payload=payload)
        self.rollout.events.append(ev)
        return ev

    def finish(self, outcome: str, final=None, **usage) -> Rollout:
        r = self.rollout
        r.outcome = outcome
        r.final = final
        usage.setdefault("wall_s", round(time.time() - self._t0, 3))
        usage.setdefault("turns", sum(1 for e in r.events if e.kind == "model_call"))
        r.usage.update(usage)
        return r

Collects events for one rollout and holds no opinion about correctness — it cannot, it has no key. emit stamps time relative to the start; finish seals the rollout with an execution state and the usage totals.

def iter_all(root: Path | None = None, dedupe: bool = True):
    """Every stored rollout, with the header it was recorded under.

    The store is append-only, so re-running a key that is already on disk
    (`run.py --no-resume`) leaves two records for it rather than replacing
    one. That is the correct behaviour for a log — the earlier attempt really
    did happen — but a derived view must not count it twice. So the default
    here is last-write-wins per (solver_config, task_id, run_idx): the log
    keeps everything, metrics see one row per rollout.

    Pass dedupe=False to audit the raw log, including superseded records.
    """
    base = root or TRACES
    records = []
    for path in sorted(base.glob("*/*.jsonl")):
        header, rollouts = read_trace(path)
        records.extend((header, r) for r in rollouts)
    if not dedupe:
        yield from records
        return
    latest: dict[tuple, tuple] = {}
    for header, r in records:
        latest[r.key] = (header, r)          # later lines win
    for header, r in latest.values():
        yield header, r

                seed: int | None = None) -> Rollout:

    budget = Budget(usd_cap=cfg.usd_budget, turn_cap=cfg.max_turns)
    schemas = toolmod.schemas(cfg.tools)

    messages = [
        {"role": "system", "content": cfg.prompt},
        {"role": "user", "content": task.problem},
    ]
    rec.emit("run_start", task_id=task.task_id, run_idx=run_idx, config=cfg.header())

    while True:
        try:
            budget.check("turn")
        except BudgetExceeded as e:
            rec.emit("error", fault=e.kind, message=str(e))
            return _stop(rec, "max_turns" if e.kind == "turn" else "budget_exceeded", budget)

        rec.emit("model_call", n_messages=len(messages), model=cfg.model.model)
        try:
            comp: Completion = provider.complete(messages, schemas)
        except ProviderTimeout as e:
            # A harness failure. Not a wrong answer.
            rec.emit("error", fault="timeout", message=str(e))
            return _stop(rec, "timeout", budget)
        except ProviderError as e:
            rec.emit("error", fault="provider", message=str(e))
            return _stop(rec, "error", budget)

        budget.turns_used += 1
        from agent.providers import usd as _usd
        budget.charge(comp.tokens_in, comp.tokens_out,
                      _usd(cfg.model, comp.tokens_in, comp.tokens_out))
        rec.emit("model_response", text=comp.text,
                 tool_calls=[c["name"] for c in comp.tool_calls],
                 tokens_in=comp.tokens_in, tokens_out=comp.tokens_out)

        if not comp.tool_calls:
            low = (comp.text or "").lower()
            if any(m in low for m in REFUSAL_MARKERS):
                return _stop(rec, "refused", budget, final=None)
            # No tool call and no refusal: nudge once, then let the turn cap bite.
            messages.append({"role": "assistant", "content": comp.text})
            messages.append({"role": "user",
                             "content": "Call a tool, or submit_answer if you are done."})
            continue

        messages.append({"role": "assistant", "content": comp.text or None,
                         "tool_calls": comp.tool_calls})

        for tc in comp.tool_calls:
            rec.emit("tool_call", tool=tc["name"], args=tc["args"])
            try:
                result = toolmod.call(tc["name"], tc["args"], budget)
            except toolmod.SubmitAnswer as s:
                rec.emit("final", value=s.value, reasoning=s.reasoning)
                return _stop(rec, "submitted", budget, final=s.value)
            except BudgetExceeded as e:
                # The trip kind matters: hitting the turn cap is `max_turns`,
                # hitting the spend cap is `budget_exceeded`. Flattening the two
                # would lose the distinction the taxonomy exists to make.
                rec.emit("error", fault=e.kind, message=str(e))
                return _stop(rec, "max_turns" if e.kind == "turn" else "budget_exceeded",
                             budget)

                result = {"error": f"{type(e).__name__}: {e}"}
            rec.emit("tool_result", tool=tc["name"], result=result)
            messages.append({"role": "tool", "name": tc["name"],
                             "content": json.dumps(result)})

def _limits():
    """Best-effort resource caps in the child, before exec.

    Not every limit is enforceable on every platform — macOS refuses to start
    a CPython child under RLIMIT_AS, and RLIMIT_NPROC is per-user there rather
    than per-process. A limit we cannot set is skipped rather than fatal; the
    wall-clock timeout in run_python is the backstop that always holds.

        caps.append((resource.RLIMIT_NPROC, (64, 64)))

            resource.setrlimit(what, vals)
        except (ValueError, OSError):
            pass

function_with_backoffL22–43


def _with_backoff(fn, attempts: int = MAX_ATTEMPTS):
    """Backoff for faults that escape the loop entirely — i.e. we failed to
    obtain a trace at all.

    Note what is deliberately NOT retried here: a provider error or timeout
    that the loop caught. Those are recorded as the outcomes `error` and
    `timeout` and left in the corpus, because silently re-rolling them until
    one succeeds is precisely how a reported accuracy gets inflated. The error
    rate is a result, not a nuisance to be retried away.
    """
    last = None
    for i in range(attempts):
        try:
            return fn()
        except ProviderError as e:
            last = e
            if i == attempts - 1:
                raise
            time.sleep(BASE_BACKOFF_S * (2 ** i) * (1 + random.random() * 0.3))
    raise last  # pragma: no cover

    if raw is None:

def render(rollout: Rollout, task: Task, *, blinded: bool = True,
           model_names=(), graded_outcome: str | None = None) -> tuple[str, dict]:
    """Build the judge prompt. Returns (prompt, audit).

    `blinded=False` is the SAME function with a flag: it leaves the final
    answer and the GRADED outcome in. The diff between the two prompts is the
    slide, and `graded_outcome` is the part that does the damage — telling a
    judge the answer was right is what makes it rationalise the reasoning.
    Passing the raw execution state instead would leak nothing, and the
    ablation would silently measure noise.
    """
    submitted = "" if rollout.final is None else str(rollout.final).strip()
    ids = _identifiers(rollout, model_names)

    parts = [SYSTEM, "", f"PROBLEM:\n{task.problem}", ""]
    for ev in rollout.events:
        if ev.kind == "model_response":
            text = (ev.payload.get("text") or "").strip()
            if not text:
                continue
            parts.append(f"NARRATION:\n{text}\n")
        elif ev.kind == "tool_call" and ev.payload.get("tool") == "python_exec":
            parts.append(f"TOOL CODE:\n{ev.payload['args'].get('code','')}\n")
        elif ev.kind == "tool_result":
            res = ev.payload.get("result", {})
            parts.append(f"TOOL STDOUT:\n{str(res.get('stdout','')).strip()}\n")
        # `final`, `run_start`, `model_call` and `error` events are never rendered:
        # they carry the submission, the pinned config and provider error strings.

    if not blinded:
        parts.append(f"FINAL ANSWER: {submitted}")
        parts.append(f"OUTCOME: {graded_outcome or rollout.outcome}")

    parts.append(TASK_BLOCK)
    prompt = "\n".join(parts)

    audit = _audit(prompt, rollout, submitted, ids, blinded)
    if blinded and audit["hard_leaks"]:
        raise BlindingLeak(
            "blinding failed; these must never reach a blinded judge: "
            + ", ".join(audit["hard_leaks"])
        )
    return prompt, audit

def pass_at_k(n: int, c: int, k: int) -> float:
    """P(at least one of k succeeds). Unbiased from n trials, c successes."""
    if k > n:
        raise ValueError(f"k={k} exceeds n={n}")
    if n - c < k:
        return 1.0
    return 1.0 - comb(n - c, k) / comb(n, k)

def majority_at_k(answers: list, key, k: int, trials: int = 2000,
                  rng: random.Random | None = None) -> float:
    """P(the modal answer of k samples is correct). Estimated by resampling."""
    if not answers or k <= 0:
        return 0.0
    rng = rng or random.Random(20260907)
    hits = 0
    for _ in range(trials):
        draw = [rng.choice(answers) for _ in range(k)]
        counts: dict = {}
        for a in draw:
            counts[a] = counts.get(a, 0) + 1
        best = max(counts.values())
        modal = [a for a, v in counts.items() if v == best]
        if rng.choice(modal) == key:
            hits += 1
    return hits / trials

Estimates the chance that the modal answer of k samples is correct, by resampling the observed answers. Ties are broken at random rather than by first-seen, so the estimate does not inherit the order the rollouts happened to finish in.

functionbootstrap_ciL51–66


def bootstrap_ci(values: list[float], stat=None, n_boot: int = 2000, alpha: float = 0.05,
                 rng: random.Random | None = None) -> tuple[float, float]:
    """Percentile interval. Resample the CLUSTER (a task), not the rollout —
    rollouts within a task are correlated, and ignoring that understates the
    interval (Miller, 2024)."""
    if not values:
        return (float("nan"), float("nan"))
    stat = stat or (lambda xs: sum(xs) / len(xs))
    rng = rng or random.Random(20260907)
    m = len(values)
    draws = sorted(stat([values[rng.randrange(m)] for _ in range(m)]) for _ in range(n_boot))
    lo = draws[int((alpha / 2) * n_boot)]
    hi = draws[min(n_boot - 1, int((1 - alpha / 2) * n_boot))]
    return (lo, hi)

A percentile interval — and the choice of what to resample is the methodological point. The values are per-task rates, not per-rollout outcomes: ten rollouts of one problem are correlated, and treating them as ten independent samples yields an interval far too narrow.

functioncohens_kappaL26–37


def cohens_kappa(a: list[str], b: list[str]) -> float:
    """Agreement above chance. Reported alongside raw agreement because raw
    agreement on a skewed label distribution flatters every judge."""
    n = len(a)
    if n == 0:
        return float("nan")
    obs = sum(x == y for x, y in zip(a, b)) / n
    ca, cb = Counter(a), Counter(b)
    exp = sum((ca[l] / n) * (cb[l] / n) for l in set(a) | set(b))
    return 1.0 if exp == 1 else (obs - exp) / (1 - exp)

    does the verdict change when the judge is allowed to see the answer?"""

        slot[(_key(v), v.judge_model)] = v.label

def _stratified_ablation(checked, n: int) -> set:
    """Pick the traces to ALSO judge unblinded.

    Taking the first n in sorted order looks harmless and is not: with several
    solver configurations — an effort sweep produces twelve — the whole
    ablation lands inside whichever one sorts first, and the blinding effect
    gets measured on one arm and reported as if it covered the study. So the
    sample is round-robin across (solver_config, correct/incorrect) buckets,
    under a fixed seed.
    """
    if n <= 0:
        return set()
    buckets = defaultdict(list)
    for r, _task, v in checked:
        if r.outcome != "submitted":
            continue
        buckets[(r.solver_config, v.label)].append(r)
    rng = random.Random(20260908)
    for v in buckets.values():
        rng.shuffle(v)
    keys = sorted(buckets)
    picked, i = set(), 0
    while len(picked) < n and any(buckets[k] for k in keys):
        k = keys[i % len(keys)]
        if buckets[k]:
            picked.add(buckets[k].pop().key)
        i += 1
    return picked

def stratified(rollouts, outcomes, n: int, seed: int = 20260907):
    """Stratified across the three solver configs AND across correct/incorrect,
    so the calibration set cannot be accidentally all-easy."""
    strata = defaultdict(list)
    for r in rollouts:
        o = outcomes.get((r.solver_config, r.task_id, r.run_idx))
        if o in ("correct", "incorrect"):
            strata[(r.solver_config, o)].append(r)
    rng = random.Random(seed)
    for v in strata.values():
        rng.shuffle(v)
    picked, i = [], 0
    keys = sorted(strata)
    while len(picked) < n and any(strata[k] for k in keys):
        k = keys[i % len(keys)]
        if strata[k]:
            picked.append(strata[k].pop())
        i += 1
    return picked
