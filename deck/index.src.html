AI-Math Conference · Workshop

How do we actually know an AI agent is good at math?

Most agent evaluations report one number: accuracy. That number hides four separate questions — did it get the right answer, was the reasoning sound, what did it cost, and would it do it again — and it is usually produced by an apparatus nobody could rerun.

A harness is a measurement apparatus. A judge is one instrument inside it. Harness engineering is what makes the measurement reproducible; judge hygiene is what makes that instrument trustworthy. Neither produces a meaningful number alone.
Session 1 · 40 min

Harness engineering

Everything that is not the model. The central commitment: everything downstream of execution is a pure function of an append-only event log.

  • Model versus agent: why scoring the answer stops working once there are tool calls and turns
  • The four axes — outcome, process, cost, reliability — and why most reports answer one
  • Trace-first architecture: execution and grading separated by the log
  • Config pinning: model string, prompt hash, temperature, tool set
  • Seven outcomes, not two. An API timeout is a harness failure, not a wrong answer
  • Budget enforced at the tool boundary, because instructions do not constrain spend
  • Rollout orchestration: concurrency, backoff, resumption
  • pass@k versus pass^k, bootstrap intervals, cost per successful solve
Session 2 · 40 min

LLM-as-a-judge

Using a language model as a grader where no deterministic check exists — and recognising that most of the time one does.

  • Where a judge belongs: deterministic where you can, judged where you must
  • The escape rate — disclosing how much of a number was not decided by code
  • Blinding the judge to the outcome, demonstrated live rather than asserted
  • Blinding to provenance, and why two judges from different families
  • Discrete rubric anchors instead of a numeric scale; mandatory evidence spans
  • The rotation design, and the self-preference it excludes rather than measures
  • Inter-judge agreement and judge severity as headline numbers
  • Validation against human labels — an unvalidated instrument is not a measurement

You leave withTwo one-page checklists — ten rules for the harness, ten for judge hygiene — and the repository.

Both payloads follow one pattern

Define it → show it done wrong → show it done right → hand you the artifact. For the harness, “wrong” is inline grading with a boolean outcome and an unpinned config. For the judge, “wrong” is a single unblinded judge on a 1–10 scale, deployed on the one question a deterministic check already answers.

Deliberately not covered

Multi-agent coordination, long-horizon autonomy, side-effecting tools, and annotation at scale. This workshop teaches how to measure an agent, not how to build one — and says so rather than gesturing at breadth it does not have.
