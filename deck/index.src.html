Workshop

How do we actually know an AI agent is good at math?

1st International Conference and Workshop Mathematics and Artificial Intelligence · September 9–11, 2026

A model returns 42. The answer key says 42. Almost every evaluation you will read stops there and calls it a point. This workshop is about everything that question leaves out — and about building, live, the apparatus that answers it properly.

Evaluating an AI agent means evaluating the entire experimental system around it — not merely asking whether the final answer is correct.
Part I

Harness engineering

The infrastructure around the model that makes an experiment repeatable, controlled, measurable, comparable and reproducible. The model is one component in it.

  • What a harness is, and why the model is the easy part
  • Problem loader, experiment config, model adapter, trace collector, metrics, cost, result store — one block at a time
  • One interface over three different APIs: OpenAI, Google, xAI
  • Reasoning modes as a harness concern, and what to do when a provider does not have one
  • What the API actually exposes about reasoning — and what it does not
  • Tokens, latency and cost, collected because accuracy alone is not a result
Part II

LLM-as-a-judge

Two models can both answer 42, one by valid reasoning and one by luck. Deciding which is which needs a second instrument — and that instrument needs measuring too.

  • Why exact-answer correctness is not enough
  • A six-criterion rubric with written anchors, instead of “is this good?”
  • Structured JSON output, and what to do when it does not parse
  • Two judges per candidate, never from the candidate's own family
  • Does a higher-effort judge judge better?
  • Where judges agree, where they do not, and the bias list you must state out loud
The experiment3 models × 3 reasoning modes × 3 problems, then every solution judged by the other two models at two judge efforts.
ModelsGPT-5.6-Terra · Gemini-3.8-Flash · Grok 4.6 — each solving, and each judging the other two.
FormatConcept → intuition → architecture → components → example → code → execution → result. Runs from precomputed results, offline.
You leave withThe working harness, the judge pipeline, the problem set, the result schema and every command, in one repository.

The whole argument, in one line

Accuracy is one number from a system with at least six moving parts: which problem, which model, which reasoning mode, what it cost, how long it took, and whether the reasoning that produced it was valid. A harness makes those six recordable. A judge makes the sixth one assessable. Neither is worth anything without the other, and neither is ground truth.

Deliberately not covered

Training, fine-tuning, multi-agent coordination, tool-using agent loops, and human annotation at scale. This workshop is about how to measure a model on mathematics rigorously enough that the number means something — and it says what it does not cover rather than gesturing at breadth it does not have.
